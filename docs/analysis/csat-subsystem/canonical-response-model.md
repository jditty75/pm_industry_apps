# Canonical CSAT Response Model (`CSAT_Responses`) — contract draft 1

Contract id: `csat-response-v1`. One flat sheet, one row per `response_id`. Column order is part of the contract: **identity → context → scores → comment-derived flat columns → lineage → long text → JSON** (long text last so aggregation can read a narrow numeric range without touching comments).

Provenance legend: `CS` = CUSTOMER_SOURCE, `QD` = QUALTRICS_DERIVED, `WD` = Workday-sourced context (survey dashboard join), `SYS` = lineage generated by us, (`AI` reserved — never in this sheet).
Sensitivity: `P0` operational, `P1` customer-business (account/deployment), `P2` customer feedback/scores, `P3` personal data.

## 2. Score semantics in the model
- Blank ≠ 0. Out-of-range → null + warning (job warning counter, no values logged).
- `overall_satisfaction` is the only cross-survey KPI. `pgl_satisfaction` / `mds_satisfaction` are survey-specific and never averaged together or into Overall. If `pgl|mds_satisfaction` ≠ `overall_satisfaction`, keep both; warn count is reported (observed 5 PGL, 2 MDS).
- NPS value computed at read time: promoters (9–10) − detractors (0–6) over answered PGL responses; show only with n ≥ 10 else "low n".
- Legacy rows (`legacy_0to10`) use the *current* 1–5 fields only; legacy values are not stored.

## 3. Identity and upsert
- PK = `response_id`. Insert when absent; **no-op** when `row_hash` equal; **update in place** (increment `revision`, set `updated_job_id`/`updated_at`) when different; **retain** when absent from a later file.
- `first_*` never change. No field-level change history in V1 (revision counter + job ledger + Drive-restorable file only). Add `CSAT_Responses_Changes` (append-only) only if correction audits become a requirement.
- Within one file: duplicate `response_id` → keep the row with greatest `response_ts_utc`; tie → later file position; count reported.
- Out-of-order file: EDM stale guard on export watermark = max `_cachedDate`; plus per-row guard is impossible (no row version) → an older file can only revert a corrected response, never delete data.

## 4. Storage
Single sheet `CSAT_Responses` per destination workbook (HC_DM, SLG_DM, HENP_DM). Header row = contract column names; `contract_version` recorded in a Script Property (`CSAT_RESPONSES_CONTRACT:<appId>`) and verified on every write. Text columns formatted Plain Text. Upsert algorithm: read PK+hash columns (2 columns), build plan, append inserts with one `setValues`, patch updates by row (batched contiguous ranges), under a script lock, verify counts/headers, restore on failure (mirrors `_replaceCsatInFlightSafely_`). New DepMngr function `ingestCsatResponses(config, rows, metadata, context)` returning `{success, inserted, updated, unchanged, rejected, excluded, warnings, verification}`.

## 5. Tenant/universe rule (differs from InFlight)
InFlight keeps only *Active* deployments for HC. Responses are historical; a PGL response often arrives after a deployment leaves "Active". Universe = deployment exists in the destination's SFDC deployment master (any status) **or** `sub_region` route matches and Jeff accepts orphan retention (decision D5). Rows outside the universe are *quarantined by count* (reported, not written).

## 6. Free-text handling
Normalize CRLF→LF, strip NUL/control chars (keep \n \t), trim, cap 49,000 chars (flag `truncated` count). Store as Plain Text; additionally prefix a leading `'` only if the first char is `= + - @` (sheet formula-injection defense); the API strips that single prefix on read. Never treat as HTML: server returns text, UI renders with `textContent`/escape, preserves line breaks via CSS `white-space: pre-wrap`, linkifies nothing in V1. List DTOs omit comment text (preview ≤ 140 chars on request); detail DTO returns full text. Logs, ledger, errors, caches, notification payloads: **counts only, never content**. Fixtures: synthetic strings only.

## 7. Lineage vs ledger
Per-response lineage lives on the row; per-run totals live in `EdmJobLedger`. Raw CSV backup (`DHM_CSAT_Imports`) must be **disabled** for Responses (`skipBackup:true`) unless restricted — see decision D4.
